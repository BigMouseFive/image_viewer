# Amazon A+ 修图背景与视觉规则

本指南用于本 Skill 的 `A+L01`–`A+L05` 修图任务。它是安全、可复核的工作约束，不替代人工意见或 Amazon Seller Central 中针对具体站点、类目和品牌的最新政策。冲突时，优先级为：**人工意见 → 产品主图事实 → 当前任务上下文 → 本指南的保守规则**。

## 1. 画布与输出

- 每张候选图必须是可解码的真实 **PNG**，精确 **970 × 600 px**。这是本项目固定的 `97:60` 画布；以 `970×600` 这一硬性尺寸为准，不要称为或强行调整为 `16:10`。
- 不要通过拉伸现有图硬凑尺寸。应在保留比例的前提下重新排版、扩展背景或重新生成合适构图。
- 保持清晰边缘、自然阴影和可读文字；建议使用 RGB/sRGB 工作流，避免意外的透明画布、损坏的 ICC/色彩转换或过度压缩伪影。
- 提交前用 `scripts/validate_image.py` 校验尺寸、格式、可解码性、文件大小和非近纯色信号。该校验不能证明产品事实或文案合规。

## 2. 产品主图是视觉事实依据

任务的 `main_image` / `reference_image` 是对产品本体作判断的首要依据。修改前必须并排核对待改图、主图、人工意见和原 prompt/copy。

必须与主图一致的内容包括：

- 整体轮廓、长宽比例、开口、边缘、把手、按键、接口、缝线和可见结构；
- 颜色、表面光泽、材质、纹理、金属/塑料/织物属性以及透明或半透明部分；
- 组件、配件、包装、款式/变体、套装内物品和画面中的产品数量；
- 产品摆放方向、可见面和连接关系。看不到的背面、内部或功能细节不能凭想象补全。

原始生成 prompt、计划文案、商品标题和五点描述可帮助理解模块意图，但不能推翻主图可见事实，也不能单独证明未展示的颜色、配件、性能或使用场景。

当主图、任务信息和人工意见不足以确定产品事实时：不要用“看起来合理”的替代物。提交 `needs_human_input`，写明缺少什么角度、变体、数量或文案确认。

## 3. 构图与背景

1. **产品优先。** 主体应易于辨认，不被巨大的场景物、装饰、特效、文字或裁切掩盖。
2. **背景干净且相关。** 可使用低噪声纯色、柔和渐变、简洁材质或与模块主题直接相关的受控场景；背景不能制造不存在的产品部件、配件、套装数量或性能暗示。
3. **保留有效内容。** 人工意见没有要求改变的合格构图、产品、文字和视觉风格应保留。一次任务只做解决问题所需的最小修改。
4. **避免视觉噪声。** 避免杂乱纹理、强烈频闪/摩尔纹、无关漂浮物、难以解释的反射、遮挡主体的烟雾/光晕，以及会让产品颜色失真的环境色。
5. **合理裁切。** 不裁掉主体关键结构、配件数量或文字；若设计需要局部特写，应仍能让用户理解展示的部位与完整产品的关系。
6. **场景不得替代证据。** 人物、食品、液体、儿童、医疗/安全/性能情境等容易形成额外宣称。除非主图、已批准的文案和人工意见明确支持，优先使用中性背景而不是推断性的生活场景。

## 4. 文字与安全区

文字不是每次修图都必须添加。若任务只是产品外观、数量、背景或裁切问题，不要擅自新增卖点、标签或品牌元素。

当前接口不会强制一个 Amazon 官方像素安全区；以下是防止显示边缘裁切的**保守制作建议**：

- 所有关键文字、标志和必须完整显示的图标，建议至少距左右边缘 **50 px**、距上下边缘 **35 px**；即尽量放在 `x=50…920`、`y=35…565` 内。
- 不要让文字贴近产品轮廓、重要配件或高反差复杂背景；给字形、描边、阴影和阿拉伯文连写保留实际可见空间。
- 使用足够的对比度、清晰字号和干净字距。不要用背景同色、过细字体、拉伸字形或低对比透明文字。
- 若有英语与阿拉伯语，逐字检查拼写、语法、方向、换行、标点和完整性；阿拉伯文应保持正确的 RTL 连写和阅读顺序，不能镜像、断字或被裁切。
- 不把已有文字改写为更强的功能、效果、比较或保证。文字事实无法确认时，删除/保留原有有效文本或报告不确定性，而不是编造。

## 5. 禁止或高风险内容

除非人工意见明确要求删除，修图不应引入以下内容；其中大多数也不应保留在新生成区域：

- 价格、折扣、优惠券、促销倒计时、限时/最低价等销售刺激；
- 星级、评分、评论摘录、销量排名、虚构奖项或“best seller”类背书；
- Amazon、Prime、Amazon 页面元素、竞品商标或容易造成平台关联/比较的元素；
- URL、二维码、社媒账号、电话、电子邮件、地址或其他站外导流/联系方式；
- 水印、生成器签名、未授权素材标记、界面截图或明显的 AI 伪影；
- 未由主图和经批准文案支持的性能、认证、医疗、安全、环保、兼容性、耐用性、尺寸、数量或结果宣称；
- 误导性的前后对比、夸张比例、虚假套装/配件、错误颜色或错误变体；
- 暴力、成人、歧视、危险使用、侵权角色/标识或不适合商品详情页的内容。

不确定某项宣称是否被支持时，按“不支持”处理，并在 `uncertainties` 中记录所需的人类确认。

## 6. 五模块一致性：`A+L01`–`A+L05`

同一 SKU 的五张图是一个视觉系统，不是五个互不相关的产品版本。

| 模块 | 常见目的 | 一致性要求 |
| --- | --- | --- |
| `A+L01` | Hero/banner | 最清楚地建立产品本体、颜色和整体气质。|
| `A+L02`–`A+L05` | 功能、细节、场景或补充卖点 | 可改变视角/场景以说明模块，但不能改变产品型号、颜色、结构、配件或数量。|

每次修改任一模块时，至少快速比对同 SKU 的其余四张：

- 产品轮廓、主色、材质、透明度、连接件和套装数量是否一致；
- 品牌色、光线方向、阴影强度、摄影/插画风格和背景复杂度是否协调；
- 同一功能、尺寸、配件或文案是否在不同模块中互相矛盾；
- 是否存在某一张图把旧变体、错误包装或多余物体带回系列中；
- 每张是否仍为 `970×600`，且文字布局没有挤压到边缘。

不需要为了“统一”而重做未被任务点名且本来合格的其他模块。只在当前任务中修正相关冲突，并把跨模块无法确认的问题报告给人工。

## 7. 提交前人工检查清单

- [ ] 候选图是 PNG，`970×600`，未被拉伸，产品没有不合理裁切。
- [ ] 产品本体、颜色、材质、结构、配件、包装和数量与主图一致。
- [ ] 每条人工意见都已解决，未涉及的合格内容被保留。
- [ ] 背景简洁、相关且不制造不受支持的事实或效果。
- [ ] 新增/保留的文字完整、可读、真实，并处于保守安全区内。
- [ ] 没有价格、促销、评分、Amazon/Prime、URL、联系方式、水印或未经支持的宣称。
- [ ] 与同 SKU 的 `A+L01`–`A+L05` 没有可见的产品或视觉矛盾。
- [ ] 不确定项已转为 `needs_human_input`，而不是用猜测的图片提交。
